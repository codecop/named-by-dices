## api_push.py

Pushes local commits to the remote branch via the GitHub REST API.

**Why:** in the cloud sandbox, `git push` (smart-HTTP receive-pack) is blocked by the sandbox proxy (403), while the REST API (api.github.com) is allowed.
**Where needed:** only in the cloud instance. Locally, plain `git push origin <branch>` works.

**Authentication (in this order):**

1. `gh api` transport — if the `gh` executable is installed and authenticated, all API calls go through `gh api` and gh supplies the token itself. This is the mode that works inside the cloud sandbox, where raw HTTP with a token is rejected (401/403).
2. Explicit token via urllib — `API_PUSH_TOKEN` (environment) or `~/.push-token` (`chmod 600`, never commit it!). Used outside the sandbox or when gh is unavailable.

The repository is derived from `git remote get-url origin`. See also `.agents/skills/commit/SKILL.md`.

**Usage in a new session:**

```
gh repo clone <owner>/<repo>
# either: gh is authenticated (gh auth login / GH_TOKEN present) -> nothing else needed
# or:     echo '<token-with-repo-write>' > ~/.push-token && chmod 600 ~/.push-token
git add -A && git commit -m "<msg>

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>"
python3 scripts/api_push.py
```
