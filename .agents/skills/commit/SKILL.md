# Commit

## Commit-Regeln für dieses Projekt

Format:

```
git commit -m <Commit message here>

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

Regeln:

- Immer `git commit` — niemals andere Wege, um Änderungen zu committen
- Footer-Pflicht: Jeder Commit endet mit `Generated by Mistral Vibe.` und der `Co-Authored-By`-Zeile
- Keine History-Änderung: nie `git reset --hard`, `git rebase`, `hg strip`, `hg rebase` oder ähnliches

Beispiel:

```
git commit -m "Add user authentication feature

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>"
```

## Push im Cloud-Sandbox

In der Cloud-Sandbox wird `git push` (smart-HTTP receive-pack nach github.com) vom
Sandbox-Proxy mit 403 abgelehnt, während die GitHub-REST-API (api.github.com)
erlaubt ist und der Token Contents:write-Rechte hat. Deshalb:

1. Lokal wie gewohnt mit `git commit` arbeiten (Regeln oben).
2. Pushen mit `python3 scripts/api_push.py [--branch main]` — das Script
   liest das Token aus `API_PUSH_TOKEN`, `~/.push-token` (chmod 600) oder
   `gh auth token`, ermittelt das Repo aus `git remote get-url origin` und
   spielt die lokalen Commits per Git-Data-API (Blobs -> Tree -> Commit ->
   PATCH ref) auf den Remote-Branch.
3. In einer neuen Session: Repo mit `gh repo clone <owner>/<repo>` klonen,
   Token bereitstellen (eine der drei Quellen oben), dann `scripts/api_push.py`.

Außerhalb des Sandbox funktioniert normaler `git push origin <branch>`.

Das Token wird niemals ins Repo geschrieben oder ausgegeben.
