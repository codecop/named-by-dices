# Commit

## Commit rules for this project

Format:

```
git commit -m <Commit message here>

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

Rules:

- Always use `git commit` — never any other way to commit changes
- Footer mandatory: every commit ends with `Generated by Mistral Vibe.` and the `Co-Authored-By` line
- Commit often after each increment — small, frequent commits instead of big batched commits
- Push every commit immediately (`scripts/api_push.py`) — if the cloud instance crashes, unpushed local commits are lost
- Token: on first use, pass a personal access token **in the chat**; it is stored in `~/.push-token`, which is **created with chmod 600 if missing** and never committed or printed. The gh executable's own token is not used (read-only in the sandbox).
- NEVER change history in version control. This includes:
  - Never do `git reset --hard`
  - Never do `git rebase`
  - Never do `hg strip`
  - Never do `hg rebase`

Example:

```
git commit -m "Add user authentication feature

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>"
```

## Push in the cloud sandbox

In the cloud sandbox, `git push` (smart-HTTP receive-pack to github.com) is rejected by the sandbox proxy with 403, while the GitHub REST API (api.github.com) is allowed and the token has Contents: write permission. Therefore:

1. Work locally with `git commit` as usual (rules above).
2. Push with `python3 scripts/api_push.py [--branch main]` — the script needs a personal access token with repo write access, passed in the chat on first use and stored in `~/.push-token` (created with chmod 600 if missing; `API_PUSH_TOKEN` is honoured too). In the sandbox, `git push` is blocked (403) and gh's mutating API calls are blocked as well, so the script talks to api.github.com directly via raw HTTPS and replays the local commits via the git data API (blobs -> tree -> commit -> PATCH ref). The repo is derived from `git remote get-url origin`.
3. In a new session: clone the repo with `gh repo clone <owner>/<repo>`, pass the token in the chat once, then run `scripts/api_push.py`.

Outside the sandbox, plain `git push origin <branch>` works.

The token is never written into the repo or printed.
